# توسيع المنصة لتشمل جميع الأعمار مع "الطفل الداخلي"

الفكرة: المنصة ليست للأطفال فقط. البالغون يستحقون أيضاً قصصاً شخصية تلامس طفلهم الداخلي. سنوسّع النظام مع الحفاظ على الأمان والحرية المدروسة، وترك القرارات الحساسة للإدارة بعد التحقق من هوية المستخدم.

## 1) إعادة تعريف الفئة العمرية

- الحفاظ على حقل `hero_age` رقمي حر (0-99).
- اشتقاق تلقائي لـ `age_bucket`: `early_child` (3-6)، `child` (7-12)، `teen` (13-17)، `young_adult` (18-30)، `adult` (31-55)، `senior` (56+).
- تحديث برومبت توليد النص ليختار النبرة تلقائياً:
  - أطفال: مغامرة، بساطة، إيقاع سريع.
  - يافعون: اكتشاف الذات، تحديات، صداقة.
  - بالغون: ملامسة الطفل الداخلي، حنين، تأمل، رحلة داخلية، شفاء.
- خيار جديد في `/create`: "نوع الرحلة" (مغامرة / حنين / شفاء / تأمل / خيال) — يظهر تلقائياً للبالغين.

## 2) كشف العمر من الصور (تحقق إجباري للبالغين)

- دالة خادم `estimateAgeFromPhoto` تستدعي `google/gemini-3-flash-preview` مع الصورة وترجع `{estimated_age, confidence, is_minor_likely}`.
- تُستدعى تلقائياً عند رفع صورة الشخصية.
- منطق التحقق:
  - عمر مدخل ≥ 18 والصورة تُشير لقاصر بثقة عالية → إيقاف الطلب فوراً ووضعه في `pending_age_verification` — قرار الأدمن.
  - عمر مدخل < 18 والصورة تُشير لبالغ → تحذير للأدمن فقط.
- حقول جديدة على `orders`: `photo_age_estimate`, `photo_age_confidence`, `age_verification_status`.

## 3) نظام المراجعة الإدارية الإلزامية للبالغين

- حقل `requires_admin_review` (boolean) يُشغَّل تلقائياً عند:
  - `hero_age >= 18` (كل قصص البالغين).
  - `age_verification_status = 'pending'`.
  - أي علم محتوى حساس من المصفاة.
- الطلب يقف عند حالة جديدة `pending_review` قبل أي استهلاك اعتمادات AI.
- الأدمن: يوافق / يرفض بسبب / يطلب تعديل / يطلب توثيق هوية إضافي.
- صفحة أدمن جديدة `/admin/review-queue` تعرض:
  - نص فكرة القصة من المستخدم.
  - صور الشخصيات.
  - العمر المدخل + العمر المقدَّر من AI.
  - أعلام المحتوى المكتشفة مع تصنيفها (أحمر مطلق / أصفر قابل للنقاش).
  - سجل المستخدم السابق (كم طلب سابق، كم قُبل، كم رُفض).
  - أزرار: موافقة / رفض بسبب / طلب توثيق هوية / حظر.

## 4) مصفاة المحتوى (Content Safety Filter)

دالة خادم `screenStoryRequest` تفحص طلب المستخدم وتُصنِّف الأعلام إلى فئتين:

**فئة أ — رفض تلقائي مطلق (لا يصل للأدمن أصلاً):**
- عنف دموي / تعذيب / أذى جسدي فعلي.
- إساءة دينية أو طائفية أو تحريض.
- ذكر شخصيات حقيقية بالاسم (سياسيون، مشاهير، شخصيات دينية).
- محتوى يتضمّن قاصرين في سياقات غير ملائمة (خط أحمر قانوني مطلق).

**فئة ب — تصعيد للأدمن مع تحقق من هوية المستخدم:**
- محتوى رومانسي / حميمي / جنسي (قد يكون شخصياً مشروعاً لبالغ).
- إشارات نفسية حساسة (اكتئاب، فقد، ذكريات مؤلمة).
- كحول / مواد / محتوى استهلاكي بالغ.
- سياسات: هذه القصص لا تُولَّد قبل موافقة الأدمن + تأكيد أن المستخدم بالغ (عبر توثيق العمر من الصورة أو من هوية إضافية إن طلبها الأدمن).

يستخدم `google/gemini-3.1-flash-lite` (رخيص وسريع) بمخطط JSON.
كل قرار يُسجَّل في `content_screening_log` مع الفئة والسبب.

## 5) تدفق حالات الطلب الجديد

```text
draft
  → screening (auto-filter)
      → [rejected] إذا فئة أ
      → [needs_review] إذا فئة ب أو بالغ
      → admin_decision:
          → approved → paid → generating → delivered
          → needs_identity → المستخدم يرفع توثيق → admin_decision
          → rejected (مع سبب واضح)
```

## 6) واجهة الإنشاء `/create`

- رسالة توضيحية أعلى الصفحة: "منصة للجميع — من الأطفال حتى الكبار. أخبرنا عمرك ونصنع لك قصتك."
- عند اختيار عمر ≥ 18:
  - إظهار حقل "نوع الرحلة".
  - إشعار شفاف: "الطلبات للبالغين تخضع لمراجعة إدارية قبل التوليد (حتى 24 ساعة). للمحتوى الشخصي/الحميمي قد نطلب توثيقاً إضافياً للعمر — قرارك الشخصي محمي وسري."
  - رابط "اقرأ سياسة المحتوى".
- صفحة جديدة `/content-policy` تشرح المسموح والممنوع والقرارات الإدارية.

## 7) قاعدة البيانات

Migration واحدة تضيف:
- `orders`: `age_bucket`, `journey_type`, `photo_age_estimate`, `photo_age_confidence`, `age_verification_status`, `requires_admin_review`, `admin_review_note`, `admin_reviewed_at`, `admin_reviewed_by`, `content_flags jsonb`, `identity_verification_status`, `identity_document_url` (خاص، للأدمن فقط).
- جدول `content_screening_log` (order_id, category, flags, decision, model_used, created_at).
- علم ميزة `adult_stories_enabled` (افتراضياً on).
- علم ميزة `intimate_content_enabled` (افتراضياً off — يُشغّل من الأدمن عند الجاهزية).
- `review_queue_capacity` في `pricing_settings`.

## 8) الملفات المطلوب إنشاؤها/تعديلها

جديدة:
- `src/lib/content-screening.functions.ts` — مصفاة + تقدير العمر + توثيق الهوية.
- `src/routes/admin.review-queue.tsx` — قائمة المراجعة الموحدة.
- `src/routes/content-policy.tsx` — سياسة المحتوى.
- `src/routes/verify-identity.$id.tsx` — صفحة رفع توثيق العمر للمستخدم عند طلب الأدمن.

معدَّلة:
- `src/lib/orders.functions.ts` — استدعاء المصفاة قبل الدفع، منطق `pending_review` و `needs_identity`.
- ملف برومبت القصة — منطق `age_bucket` والنبرة و`journey_type`.
- `src/routes/create.tsx` — رسائل التوسع، حقل نوع الرحلة، تنبيه المراجعة.
- `src/routes/admin.tsx` — رابط "قائمة المراجعة" مع badge للعدد المعلق.
- `src/routes/my-orders.tsx` — عرض حالات `pending_review` و`needs_identity` بوضوح.

## 9) الأمان القانوني والخصوصية

- كل طلب مرفوض يُحفظ سببه مع الطابع الزمني.
- كل قرار أدمن يُسجَّل في `audit_log`.
- الصور والوثائق في الطلبات المرفوضة تُحذف تلقائياً بعد 7 أيام.
- توثيق الهوية يُخزَّن في bucket خاص لا يصل إليه إلا الأدمن، ويُحذف بعد الموافقة أو الرفض بمدة محددة.
- شرط قبول واضح في `/content-policy`: القصص الشخصية الحساسة لا تُنشر في المعرض ولا تُشارك تلقائياً.

## 10) نقاط لاحقة (اختيارية)

- عرض الأنماط الفنية بحسب العمر (البالغون: واقعي/سينمائي؛ الأطفال: كرتوني/بيكسار).
- قوالب "قصة الطفل الداخلي" جاهزة كإلهام للبالغين المترددين.
- سياسة تلقائية: بعد N طلب ناجح للمستخدم البالغ، تُخفَّف متطلبات التوثيق للطلبات المشابهة.
