# روتين مراجعة تحديثات المستودع قبل النشر

## الهدف
اعتماد آلية ثابتة: عند طلبك مراجعة المستودع، أراجع آخر التغييرات، ألخّصها لك، وأنتظر موافقتك قبل أي نشر.

## كيف سيعمل
1. تكتب في المحادثة: «راجع المستودع» (أو أي صيغة مشابهة).
2. أفحص حالة الكود المُزامَن حالياً في المشروع: الملفات المتغيّرة، الوظائف المتأثرة، وأي تعارض مع المزايا الحالية.
3. أعرض ملخصاً موجزاً بالعربية:
   - ما الذي تغيّر ولماذا يهم.
   - أي مخاطر (كسر مسار، أمان، قاعدة بيانات، PWA/PDF/التوليد).
   - توصية: «جاهز للنشر» أو «يحتاج إصلاحاً أولاً».
4. لا يتم أي نشر إلا بعد موافقتك الصريحة؛ عندها أعرض زر النشر.

## قاعدة دائمة تُحفظ في ذاكرة المشروع
- لا تنشر أبداً دون طلب صريح من المستخدم.
- عند طلب «راجع المستودع»: لخّص التغييرات + المخاطر + توصية بالنشر، ثم انتظر الموافقة.

## ملاحظات تقنية
- مزامنة GitHub ثنائية الاتجاه وتلقائية؛ لا توجد مراقبة خلفية، لذا المراجعة تبدأ عند رسالتك.
- خطوة اختيارية لاحقاً: ربط موصل GitHub API لقراءة الـ commits وطلبات الدمج وعرضها داخل المحادثة مباشرة.

## ما سيُنفَّذ عند الموافقة
- إنشاء `mem://index.md` مع القاعدة الأساسية أعلاه.
- إنشاء `mem://preferences/repo-review-before-publish` بتفاصيل الروتين.
- لا تغييرات على كود التطبيق.
